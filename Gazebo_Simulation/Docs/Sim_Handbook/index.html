Gen5 Simulation Handbook

gz-sim 8 Harmonic · ArduPilot SITL · no ROS

Every world in the project, and how to bring one up. The flight worlds carry the drone and the plant; the rig worlds carry one rover against one steel target. Only two worlds matter for a demo — gen5_plant.sdf to fly, and whichever rig world shows the rover you want to talk about.

Before anything else

Set up the terminal

Once per session. Most of this already lives in ~/.bashrc; running it again is harmless.

# everything below assumes you are here cd ~/gz_ws/src/GazebooAssets export GZ_SIM_RESOURCE_PATH="$PWD/Models/converted:$PWD/Gen5Flight/models:$PWD/InspectionYard/exports:$GZ_SIM_RESOURCE_PATH" export GZ_SIM_SYSTEM_PLUGIN_PATH="$HOME/gz_ws/build:$PWD/MagnetPlugin/build:$GZ_SIM_SYSTEM_PLUGIN_PATH"

The first path lets Gazebo find the models; the second lets it find the two C++ plugins — the magnet force and the prop-strike crash detector. Skip them and the world loads with invisible models and no magnetism.

What is inside the plant

A 150 × 150 m site holding a 45 m striped steel chimney, a medium building, a small building and a gas holder. The chimney is tapered — the mission code reads its radius per segment rather than assuming one, which is why the touch works at any height. The drone spawns nose-east with its nose camera on /gen5/fpv.

Rig worlds

Worlds that carry a rover

A rig world is one rover, one steel target, and nothing else. That is deliberate: a hold result means "the magnets carried it", and anything else in the scene would muddy that. There are 203 rover worlds and 35 orbit worlds, because each pull force, diameter and orientation is its own world.

FamilyRoverWhat varies across the family
v22*OMNI The current acceptance battery. dcA/daA = seeded circumferential / axial, flat* = flat plate, *_up/*_inv = upright or hanging underneath, 50/55/60kgf = magnet strength.
hold_*, crawl_*OMNI Older static-hold and driven-crawl worlds. hold_pipe_inv_v4_55kgf.sdf is the upside-down Ø500 hold that passed.
dynaflux_v5_*, v6_*Dyna Flux Exact-CAD globe wheel. pipe/flat/axial target, held/free inspection head, wheel profile (sph75, cyl75, band75).
orbit4_cycle_*Orbit Full inspection cycle. stiff/ctr/soft = suspension spring rate. orbit4_cycle_stiff_dt1ms is the permanent default.
diag_*any Deliberately separated diagnostic sweeps. Never quote a result from a diag_ world as an acceptance result.
rover_showcase.sdfOMNI The one built to look at: a rover on top of a pipe and one hanging underneath it.
Starting up

Bring the simulation up

The short way, after a crash or a bad start

Gen5Flight/scripts/sim_stack.sh reset # world + autopilot, ~20 s Gen5Flight/scripts/sim_stack.sh status # what is running, which ports Gen5Flight/scripts/sim_stack.sh stop # kill only what it started

It opens the world and the autopilot in their own terminal windows, waits for both to be genuinely ready, and prints READY TO FLY. Add --bridge if you are flying on the transmitter, or --world gen5_plant_v3.sdf for the showcase.

After every restart

Restarting the world switches the wind off. The panel says so in red, but it does not come back by itself — press Apply again. This is exactly what went wrong in the 22 August demo.

The manual way, one terminal per part

  1. The world

    gz sim -r Gen5Flight/worlds/gen5_plant.sdf

    Wait until the drone and the striped chimney are on screen.

  2. The autopilot

    Gen5Flight/scripts/start_sitl.sh

    Wait for the STABILIZE> prompt. This launcher is mandatory — it sets the joystick flag the transmitter dongle needs.

  3. The transmitter, only if you are flying by hand

    SDL_LINUX_JOYSTICK_CLASSIC=1 python3 Gen5Flight/scripts/rc_bridge.py --check

    Move every stick once. A stick that has not moved reports itself as centred wherever it really is.

  4. Wind

    python3 Gen5Flight/scripts/wind_panel.py # window with Apply / STOP WIND # or from the command line: python3 Gen5Flight/scripts/set_wind.py --from-heading 0 --speed 10 python3 Gen5Flight/scripts/set_wind.py --off

    Wind takes about 30 s to arrive and settle. Do not read a number early.

Watching one

Attach the 3-D window to a running rover

The harness runs the simulation headless in terminal A. Terminal B opens a viewer and joins it. Both terminals must share the same GZ_PARTITION — that is the whole trick, and getting it wrong is why a viewer sometimes shows an empty world.

# terminal A — the run GZ_PARTITION=demo python3 RoverRig/scripts/run_v2.py crawl_pipe_axial crawl 20 # terminal B — the window that joins it GZ_PARTITION=demo gz sim -g

For a world you only want to look at, with no harness driving anything, one terminal is enough:

gz sim -r RoverRig/worlds/rover_showcase.sdf # rover on a pipe + one hanging under it gz sim -r RoverRig/worlds/hold_pipe_inv_v4_55kgf.sdf # the upside-down hold that passed
In a hold world, nothing happening is the result

The rover simply stays put — hanging underneath a pipe on simulated magnets. That stillness is the measurement.

Driving each rover

Run a rover test

OMNI — hold and creep on a pipe

The trace harness records the target's own contact sensor, the rocker angle and the magnet forces, so you can tell which wheels are actually touching.

# world key, seconds, sample interval, manifest python3 RoverRig/scripts/run_v22_trace.py v22dcA_55kgf 900 10.0 rig_manifest_v22d.json # the same arm seeded axially instead of circumferentially python3 RoverRig/scripts/run_v22_trace.py v22daA_55kgf 900 10.0 rig_manifest_v22d.json

Results land in RoverRig/output/trace_<world>_<secs>s.json. The interesting fields are convergence.rear_F_mean_N (the hold), and contacts.arc_case_ever, which must be false — the case is suspended and must never touch.

Worth knowing

Seed the OMNI circumferentially and it turns itself axial within about 100 seconds and stays there. Circumferential is not a stable state; the machine finds axial on its own.

Orbit — the full inspection cycle

python3 OrbitRig/scripts/run_orbit_cycle_paired4.py \ --world orbit4_cycle_stiff_dt1ms \ --package orbit11_drive4_stiff \ --tag my_run --cycles 2

It scores twelve stages per run. Two of them are the ones that count: S3 orbit lap and S5 advance. The pivot stages (S2a/S2b/S4a/S4b) fail by design — that is the known pivot-angle scrub, a parked investigation, not a regression.

Dyna Flux — the tank turn

# world, mode, tread speed m/s, seconds, run tag python3 RoverRig/scripts/dynaflux_v5_run.py dynaflux_v5_pipe_sph75_held skidv 0.026 180 MYRUN
Expect variation here

This cell is bimodal. Roughly one run in four to one in three, the rover leaves the pipe entirely instead of turning on it — measured across 30 replicates, and the archived older wheel does it too, so it is the pipe cell rather than the new wheel. A single run proves nothing; run replicates.

House rules

Three rules that keep runs honest

  • Never pkill by pattern. Kill by process ID, from a file. A pattern on a kill line has taken down a live session on this machine. Use sim_stack.sh stop or stop_stack.sh, which only kill what they started and refuse to touch anything else.
  • Check the ports before starting. udp/9002 is bound by every Gazebo world and tcp/5760 by the autopilot. A stale autopilot holding 5760 while talking to a dead world is the nastiest failure here, because everything looks connected.
  • Replicate anything contact-heavy. Contact simulation is not deterministic. One sample is an anecdote.

What was built, how it was built, and how each piece works. Everything here came from your CAD and your measurements — the masses, the magnet pull, the motor thrust and the propeller geometry are all anchored to something real, not tuned until the picture looked right.

Method

How the models were built

Every model started as one of your STEP files. The pipeline is the same each time: read the analytic CAD surfaces to get true dimensions, decimate the mesh before the millimetre-to-metre scale step, then write the SDF with masses anchored to the real machine and joints placed where the CAD puts them.

Two habits did most of the work. First, a bounding box is not a measurement — wheel radii and track widths are probed off the CAD surfaces, which is how an 8.2 % oversized wheel radius was caught and corrected. Second, predict blind, then measure: the number goes on the record before the run, so a match means something.

The models

What exists and how each one works

Gen5 drone

A 12.000 kg quadrotor from GEN5 V1 MAIN.step, carrying a 550 g Tritex UT kit and a forward probe boom. It flies on ArduPilot SITL — the same flight code as a real aircraft, not a scripted animation. Thrust comes from the KDE motor bench table: hover was predicted at 4 399 RPM from that table before flying, and the simulator settled at exactly that.

Each rotor is modelled as three aerofoil blades at 120°, with thrust applied at the propeller disc plane rather than at the motor bell. Full specifications, the weight breakdown and how to move the centre of gravity are in the companion sheet.

The magnet plugin — the rovers' heart

Gazebo has no magnetism, so it was written in C++. It pulls a link toward steel with a force that fades with distance:

F(d) = f0 × ( d0 / (d0 + d) )2 # d = gap to the steel surface

The curve is calibrated from two measurements you took on the real rover: the rear magnet pulls 50–60 kgf touching, and 20 kgf at its 4.5 mm riding gap. The rear magnet is not a point — it is five magnets along a curved case, and the plugin models the whole curve as 21 sample points. That detail is what made the upside-down pipe test finally pass: same total strength, spread along the arc, holding the tail in.

It knows the target's shape (cylinder or plate) and projects the pull onto the real surface, so a rover on a Ø500 pipe is pulled toward the curve rather than straight down.

The prop-strike crash plugin

When a propeller's swept disc meets structure with the prop turning above 150 rad/s, all four rotor joints latch to zero. Thrust dies, the aircraft falls, and the autopilot disarms with Crash: Disarming. It is on by default in both flight worlds.

The limit, stated plainly

Nothing fractures. The engine has no structural failure model at all, so the airframe and propellers are intact on the ground. The props stopping and the aircraft falling is a realistic consequence — it is not a damage model, and no survivability claim can be read into an intact aircraft.

The rovers

OMNI (7 kg), Dyna Flux (14 kg) and Orbit (18 kg), all from your STEP files with wheels, joints, magnet positions and body shapes taken from the CAD. The front magnetic wheel's 120 kgf pull is your measurement.

All of these are re-run by one command — tools/regression/run.sh --full — which checks each against its recorded bar, so no future change can quietly break a proven result. The bars live in a file the runner is only allowed to read, and the run is voided if that file changes while it is being measured against.

Honesty

What this simulation does not claim

  • No structural failure. Props stop and the aircraft falls; nothing breaks.
  • Thrust is exact at hover, optimistic in fast climb. The propeller model has no induced inflow. Fine for hover-dominated inspection flying; do not quote climb rates.
  • The Dyna Flux tank turn is bimodal. Most runs hold and are reproducible to the decimal; roughly a quarter leave the pipe. The original three-replicate result simply never happened to catch one.
  • The Orbit pivot stops a few degrees short and the static sag is 1.3–1.8× what the spring rate predicts. Both are open, both are recorded, and spring rates are not quoted outward because of it.
  • The chimney mission is validated in steady wind only. Gusting is future work.
