How the defaults were established. ArduPilot does not publish default values in its parameter documentation — they live in the C++ source. So the exactCopter-4.7.0 tag was fetched, compiled to a SITL binary, and booted three times with a clean EEPROM to read back its factory values, including the sub-trees that only exist once a subsystem is enabled. TheCubeOrange board default overlay was applied on top, because this airframe’s board ships with its own overrides.

That yields a true like-for-like comparison for 1283 of the 1315 parameters. The remaining 32 are CubeOrange-only settings that a SITL build cannot produce; they are listed separately rather than guessed at.

What the comparison exposed

Six things the diff found

Comparing against stock surfaces problems that reading the parameter list alone does not. Three are serious.

The rangefinder is dead, and its limits are impossible

The Benewake TF03 on SERIAL2 reportedNoData for all 8493 samples of the flight — distance 0.00 m throughout. On top of that,RNGFND1_MIN is 120 m whileRNGFND1_MAX is 100 m, so no reading could ever be accepted even if the sensor worked; the values look like centimetres typed into a metres field. Terrain following (TERRAIN_ENABLE = 1 ) and surface tracking are both switched on and ran throughout the flight on a sensor that has never returned a number. Either restore the sensor and fix the limits, or setRNGFND1_TYPE = 0 and disable terrain following.

The geofence was deliberately weakened from stock

FENCE_TYPE went from the default 7 (altitude + circle + polygon) down to 1 (altitude only), andFENCE_ACTION from the default 1 (RTL or Land) to 0 (Report Only). Both are changes away from the safer factory setting. As flown, a breach produces a message and nothing else, and the 300 mFENCE_RADIUS is stored but never enforced.

Eight pre-arm check groups are switched off

ARMING_SKIPCHK defaults to 0 — skip nothing. It is set to 510084, disabling eight groups of pre-arm checks. Every one needs a recorded justification or must be cleared before the baseline is sealed.

A CAN debug interface is live in production

SERIAL6_PROTOCOL was changed from -1 (disabled) to 22 (SLCAN). That is a maintenance and debugging path into the CAN bus, left enabled on the aircraft.

A compass is marked in use but was never detected

COMPASS_USE2 = 1 whileCOMPASS_DEV_ID2 andCOMPASS_DEV_ID3 are both 0. Calibration data exists for compasses that the driver did not find. Resolve which magnetometers are actually fitted before freezing the compass set.

Hover thrust still rewrites itself

MOT_HOVER_LEARN sits at its stock value of 2 (Learn and Save), so the firmware keeps overwritingMOT_THST_HOVER in flight. Nobody changed this — but it has to be set to 1 or 0 or that parameter cannot be frozen. Same pattern applies toFS_GCS_ENABLE = 0 ,ARMING_RUDDER = 2 andADSB_ICAO_ID = 0 : all factory defaults, none of them decisions anyone recorded.

Method & limitations

Aircraft values are the lastPARM record for each parameter in the dataflash log. Reference values come fromCopter-4.7.0 compiled to SITL and read over MAVLink from a clean EEPROM, plus theCubeOrange/defaults.parm board overlay. Floating-point comparison uses a relative tolerance of 1e-6.

Two caveats. Board-level defaults baked into the CubeOrange hwdef beyonddefaults.parm are not captured, which is why 32 parameters sit in Section 3. And a parameter matching its default is not automatically correct — several findings above are stock values nobody ever decided on, which is a different problem from a bad change.
